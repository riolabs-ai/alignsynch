One card, one detail

The template surfaces are the precedent the owner approved. The relationship surfaces adopt them, and vary on exactly two declared axes: the cover slot, and the working panels. Below, each of the four surfaces is drawn twice — at 390 px and at the 1126 px column (StageColumn, #687) — side by side, using only class constants that already ship.

  • One shellBoth detail pages render identity band → facts → content → actions, one <h1>, a back link to their own list.

  • Two axesCover = muted wash + monogram (template) vs stage word on the same wash (relationship). Working panels exist on the relationship only.

§2Surface 1 — the template shelf card (the precedent)

Unchanged. The relationship card in §3 is this card with the cover slot's content swapped and the action row reduced to the one action a relationship has. Grid: grid gap-6 sm:grid-cols-2 lg:grid-cols-3.

The third card is the no-type case, kept on purpose: relationshipType("relationship-basics") is undefined, so it carries no realm chip and no price line rather than a figure nobody wrote down.

§3Surface 2 — the relationship list card (axis 1: the cover slot)

Same frame, same padding, same chips, same title, same meta line, same action row — the cover slot carries the stage word exactly where the template carries its monogram, at the same 104 px and in the same 34%-ink type. One primary action, because a relationship has one.

This removes the four metric tiles. Sessions, completion, Avg alignment and Aspects become the one meta line (3 of 4 sessions · Avg alignment 2.4), formatted in lib/member/relationships.ts — the F4 fix. If the owner prefers the tiles, that is a third declared axis (metaDensity: line | tiles) and a one-line change to the projection; it is not expressed here so the two axes stay two.

§4Surface 3 — the template detail page (the shell, as it ships)

Band → facts → content → actions. The band carries the group chip (Business), the realm (Office) and the type (Staff–Manager), then exactly one <h1>, the roles sentence and the summary. The aside is 320 px and holds facts, then the actions card — “What you can do with it”, the slot §5 puts the relationship's panels in.

§5Surface 4 — the relationship detail page (same shell, axis 2: the panels)

Identical band, identical facts card, identical aside geometry, identical back link, identical section order. The relationship's one difference: where the template draws “What you can do with it”, this page draws Edit, Publish and Complete. The panels keep the working anatomy they have (a field, a sentence, one button) and take the shell's panel heading — the only type step that moves is CardTitle's text-2xl, which becomes the template's text-base font-semibold h2, because a 24 px heading in a 320 px rail is the size that made the two pages read as two products.

What this page gains, beyond the paint. A back link to All relationships (F5 — the template has had one all along), one <h1> instead of a page heading above a card title, the group/realm/type chips the template band already draws, and the same facts card in the same place. What it does not gain is a second visual language: no shadcn Card header stack, no text-2xl panel titles, no Badge beside a CHIP.
