**Measured:** 19 November 2026 · **Branch:** `wt/v2-coverage-matrix` · **Tree:** `main` at `2.0.0-rc1.3`
· **Milestone:** none — this page is evidence for triage, not a release artefact.

The v2 redesign's completion state was untracked: milestone #27 (the UI/UX pool) is empty, #1120–#1136
shipped surfaces, and nobody had counted which of the prototype's 23 screens are actually rebuilt to
their bundle. This page is that count. Every row cites the line that carries the claim, so a stranger
can open it and disagree.

## The test, before any row

A screen counts as **v2** only when **both** hold:

1. **It paints the v2 token layer** — the `action` / `status` / `scale` families (`bg-action`,
   `text-action`, `border-action`, `bg-status-chip`, `bg-scale-1…5`) resolved through
   `lib/brand-theme.ts` and `app/globals.css`, and no raw palette step: `indigo-*`, `purple-*`,
   `violet-*` or `bg-gradient-*` (the repo's own rule, `scripts/brand-classes.mjs`). Most rows are
   action tokens; a screen whose whole drawing is a status card (`create-failed`) passes on the status
   tokens, and the row names which token it is instead of quietly upgrading it.
2. **It carries the structure its bundle draws** — the stage rail, the card and panel arrangement, the
   status icon-plus-word, the copy — cited as a `file:line` in the component that renders it.

Otherwise it is **v1**. A screen I could not inspect deeply enough to decide is **`unverifiable`**, and
it is counted rather than guessed. **`absent`** means no route renders the screen; **`reference-only`**
means the prototype file is not a product surface (a flow map, a token sheet, a redirect stub).

A row that cites a docstring instead of rendered markup is a row to distrust: every row below cites the
class, the attribute or the branch that draws the thing, not the comment that describes it.

**A route existing proves nothing.** `wizard` is five files under
`dashboard/templates/[slug]/create/**` and `template-proposal` is
`dashboard/templates/[id]/propose` — both exist, and both are called built or not by what the component
draws, never by the fact that the address answers.

**What this page does not measure.** A screen, not every state of it. The bundles draw seven states of
Relationship Detail, three of Chat and five of the answer sheet; a v2 row says the surface is rebuilt,
not that each state was walked. The state-by-state walk is QA's, not a citation's.

**No screenshots.** All 19 product rows but three sit behind `requireRole` and answer
**500 `NEON_AUTH_BASE_URL is not set`** on a tree with no secrets — the documented answer for a gated
console route — and this card forbids requiring credentials. The three public routes render fixtures,
so the cited lines are decisive on their own.

## The counts

**v2 = 19 · v1 = 0 · unverifiable = 0** · absent = 0 · reference-only = 4 · **total = 23**

Of the 19 screens that are product surfaces, **all 19 are rebuilt to their bundle**.

## What the gap is

**The gap this matrix opened with is closed: the in-app template page is built (#1259).** It was the one
absent screen, and it was absent in the way a route hides — `templates.html`,
`my-template-detail.html` and `template-proposal.html` were built, but `relationship-template.html` — the
page a member reads to decide whether to start a relationship from a library template — **had no route**:
the card's own "View Details" href (`lib/member/shelf.ts:161`) was a 308 to the public catalogue
(`next.config.mjs`), so a signed-in member who asked to read a template was sent to the marketing page.
It was a dangling link rather than a missing page, which is why nothing in the gate caught it:
`data:check` E10 matched `/templates/relationship/<slug>` against the redirect rows and the redirect
resolved. #1259 deleted that row and mounted
`app/(mainlayout)/templates/relationship/[slug]/page.tsx`, so the address the constant already produced
answers inside the shell; `tests/route-redirects.test.ts` now holds the address against a redirect.

The remaining cluster is **v1 palette residue inside otherwise-v2 screens**: three screens still paint
`gray-*` / `dark:` steps in a band or two — `components/dashboard/start-page.tsx:228`,
`components/dashboard/relationships-list.tsx:213`/`:282`/`:295`,
`components/dashboard/relationship-card.tsx:143` (the card both Start and My Relationships draw) and
`app/(mainlayout)/dashboard/templates/page.tsx:220`-`:230`/`:247`-`:249`. None of it is structure — every
band, chip, rail and status word is the bundle's — but it is the difference between "built" and "built
to the drawing", and `pnpm lint` cannot see it, because `gray-*` is not the banned palette.

## How to check a row

Open the cited `file:line`. The verdict repeats there: a `bg-action` / `border-action` / `status` /
`scale` token class is test 1, and the band, chip, rail or icon-plus-word markup around it is test 2. The
`v2` rows cite both; the four `reference-only` rows cite why there is nothing
to render.
